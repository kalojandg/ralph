# Спецификация: Създаване на вагон (тип)

> Модул "Номенклатури" (ВР-NOM-04, UC-NOM-07)

---

## 1. Основни данни и идентификация

| Поле | Описание | Пример |
|------|----------|--------|
| **Наименование (Серия)** | Име на типа вагон | "Серия 21-43", "WLAB 70-71" |
| **Код** | Уникален идентификатор (UIC код) | "ТСВ" |
| **Клас на вагона** | Първа / Втора / Бизнес / Смесен | Втора класа |
| **Капацитет** | Общ брой места за продажба | 80 |
| **Тип конструкция** | Безкупеен / Купеен / Спален / Кушет | Безкупеен (Салон) |

## 2. Удобства (Amenities)

Глобални атрибути на целия вагон — показват се като иконки при търсене на разписание (TAP-TSI кодове):

- Климатик (Air conditioning)
- Wi-Fi интернет
- Електрически контакти (Power sockets) — вж. бележка по-долу
- Превоз на велосипеди
- Превоз на домашни любимци
- Бистро / Ресторант

> **Бележка за електрически контакти**: Контактите се третират на **3 нива едновременно**:
> 1. **Wagon-level amenity** (тук) — глобален флаг, че вагонът предлага контакти като услуга по принцип
> 2. **Place Property `POWER`** — маркира се на конкретни места в seat map-а, до които физически има контакт; позволява филтриране „искам място до контакт"
> 3. **Графичен елемент (код 119)** в layout JSON — иконка на щепсел, позиционирана с X/Y координати върху схемата (по желание за по-богат UI)

## 3. Схема на местата (Seat Map Layout)

### 3.1 Координатна система (OSDM Coach Layout)

- **Ориентация**: Винаги **Landscape** (пейзаж) — дължината на вагона по хоризонтала
- **Начална точка**: X=0, Y=0 в горния ляв ъгъл
- **Координати**: Положителни цели числа (без знак)
- **Размер на решетката** (`gridSize`): Определя се чрез `{ x, y }` — напр. `{ "x": 24, "y": 5 }`

## 4. Дефиниране на индивидуални места

За всяка седалка / легло се задават:

| Атрибут | Стойности | Описание |
|---------|-----------|----------|
| **Номер** | напр. "11", "42" | Поддържа пропускане на номера (липсващи места) |
| **Тип** | Седалка, Долно/Средно/Горно легло, Падаща седалка (клапа) | Определя визуалния елемент |
| **Позиция** | WINDOW, AISLE, MIDDLE_SEAT | Спрямо прозореца и коридора |
| **Ориентация** | RIGHT, LEFT, UP, DOWN | Посока на седалката спрямо осите на вагона |
| **Допълнителни** | FACE_2_FACE, SIDE_BY_SIDE, TABLE, POWER, SILENCE, WHEELCHAIR, LOWER_BED, MIDDLE_BED, UPPER_BED | OSDM Place Properties |

## 5. Типове вагони на БДЖ — разлики в Layout

### Безкупеен (Saloon / Open Space)
- **Примери**: Серия 21-43 (83 места, 2 кл.), Серия 15-63 (58 места, 1 кл.)
- Няма вътрешни преградни стени (OPEN_SPACE)
- Места групирани по двойки, често "лице в лице" с масичка
- Коридор през средата: схема 2+2 (2 кл.) или 2+1 (1 кл.)
- Има физически липсващи номера (напр. 32, 45, 82)

### Купеен (Compartment)
- **Примери**: Серия 21-50 (66 м.), Серия 19-40 (54 м.), Серия 20-47 (80 м.)
- Дълга стена (код 30) отделя страничния коридор
- Затворени купета (стени код 23/24) с по 6 или 8 места (3 срещу 3 / 4 срещу 4)

### Спален (WLAB - Sleeper)
- **Примери**: Серия 70-71 (10 кабини, 30 легла)
- Затворени кабини от едната страна на коридора
- Вертикални легла: Долно (завършва на 1), Средно (2), Горно (3)
- Мивки (код 171) във всяко купе
- Бизнес логика: Единично / Двойно / Турист

### Кушет (Couchette - BC)
- **Примери**: Серия BC (10 кабини, 60 легла)
- Подобен на спален, но само 2-ра класа
- 6 легла в кабина, без мивки
- Всички легла се продават поотделно

### Мотриса (EMU / DMU)
- **Примери**: Siemens Desiro Серия 31 (4 вагона, 244 м.), ДМВ Серия 10
- Стълби (136/137) разделят "нисък под" и "висок под"
- Широки врати с "падащи седалки" (клапа)
- Зони за инвалидни колички и велосипеди

## 6. Backend формат на данните (OSDM JSON)

Backend-ът съхранява **CoachLayout** в JSON формат:

```json
{
  "gridSize": { "x": 24, "y": 5 },
  "places": [
    {
      "number": "11",
      "coords": { "x": 2, "y": 1 },
      "direction": "RIGHT",
      "properties": ["WINDOW", "FACE_2_FACE", "TABLE"]
    }
  ],
  "internals": [
    {
      "icon": 115,
      "coords": { "x": 0, "y": 0 },
      "orientation": "RIGHT"
    }
  ],
  "signs": [
    {
      "icon": 135,
      "coords": { "x": 2, "y": 0 },
      "orientation": "DOWN"
    }
  ],
  "compartments": [
    {
      "id": "A",
      "places": ["11", "12", "15", "16", "21", "22"]
    }
  ]
}
```

> **Важно**: OSDM предава само координати и кодове. Графичните ресурси (SVG/PNG иконки) се осигуряват от Frontend приложението.

## 7. Визуално представяне (Frontend)

### Формат
- Backend изпраща **JSON** с координати и OSDM кодове
- Frontend рендерира чрез **SVG** (или Canvas) — осигурява собствен "look and feel"

### Интерактивност
- **Кликване**: Потребителят кликва върху свободно място за да го избере
- **Цветово кодиране**: Различни цветове по статус (свободно / заето / избрано / блокирано) + легенда
- **Валидация**: Не позволява избиране на заети/блокирани места
- **Временно запазване**: Избраните места се маркират "locked" по време на плащане
- **Групово поведение**: При повече пътници — предлага съседни места

---

## 8. Валидация при запис

- Броят дефинирани места на схемата == зададен общ капацитет
- Няма дублиращи се номера на места
- Всички задължителни полета са попълнени
- При грешка — съобщение и изискване за корекция
- При успех — вагонът се записва в номенклатурата и е достъпен за модул "Композиране"
